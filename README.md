# Enterprise Expert Knowledge Worker

> **"Your company's knowledge. Now agentic."**

An autonomous, production-ready enterprise knowledge worker built with **LangGraph orchestration**, **permission-aware hybrid RAG**, **claim-level factual verification**, and **human-in-the-loop governance**.

Instead of a naive `User → RAG → LLM → Answer` pipeline, the Enterprise Expert Knowledge Worker dynamically plans multi-domain queries, delegates to specialized domain agents, strictly enforces document-level permissions before model context construction, verifies evidence grounding against authoritative citations, maintains multi-turn conversational context, and halts for human auditor approval before mutating enterprise state.

## Core Technical Highlights

### 1. Permission-Aware RAG (RBAC)
- **Golden Rule**: Unauthorized documents **never reach the LLM context**.
- RBAC validation occurs **before** context assembly.
- Restricted documents (such as the *CEO Compensation Contract*, restricted to `["admin", "hr"]`) trigger an immediate Access Denied security response when queried by standard employees (`role: employee`).

### 2. Self-Correcting Hybrid Reranking
- Combines dense semantic vector embeddings with keyword occurrence scores.
- Applies **Reciprocal Rank Fusion (RRF)** to eliminate retrieval blindspots.
- If retrieved evidence confidence falls below threshold, the self-correcting loop rewrites the query with entity expansion (capped at 2 retries to prevent infinite loops).

### 3. Claim-Level Evidence Verification
- Every major factual claim in candidate answers is checked against evidence chunks.
- Claims are categorized as: `✓ Supported`, `⚠ Insufficient Evidence`, or `⚠ Conflicting`.
- Computes genuine mathematical evidence grounding scores without fabrication.

### 4. Human-in-the-Loop Action Approval
- Real action workflow: `"Create a remote-work request for Rahul"`.
- Validates employee profile and policy compliance (`POL-HR-042`).
- Halts execution and presents an interactive Action Request Card in the UI with `[Approve]` and `[Reject]` actions.
- Decisions commit state mutations to SQLite and log to the audit trail.

### 5. Multi-Turn Conversational Memory
- Resolves entity references across conversational turns:
  - *Turn 1*: "What is Product X?"
  - *Turn 2*: "What documents are required for it?" (Resolves "it" to *Corporate Health Shield*).

## The 5 Required Demo Walkthroughs

### Demo 1: Policy Investigation
- **Query**: `"What is our remote work policy?"`
- **Execution Path**: `Supervisor Agent → Policy Agent → Retrieval Agent → Verification Agent → Response Agent`
- **Output**: Detailed eligibility criteria, authorization workflow, home office stipends under `POL-HR-042`.

### Demo 2: Complex Multi-Domain Reasoning
- **Query**: `"Can Rahul purchase Product X and what documents are required?"`
- **Execution Path**: `Supervisor Agent → Planner Agent → Employee Agent → Product Agent → Policy Agent → Retrieval Agent → Verification Agent → Response Agent`
- **Output**: 7-step plan displayed in UI; evaluates Rahul's tenure and role against Corporate Health Shield requirements; provides complete document checklist.

### Demo 3: Human-in-the-Loop Sensitive Action
- **Query**: `"Create a remote-work request for Rahul."`
- **Execution Path**: `Supervisor Agent → Planner Agent → Employee Agent → Policy Agent → Verification Agent → Human Approval Gate`
- **Output**: Action card generated; clicking `[Approve]` commits the authorization to local SQLite and updates audit logs.

### Demo 4: Contract SLA & Restrictions Analysis
- **Query**: `"Show me the restrictions in the Vendor ABC contract."`
- **Execution Path**: `Supervisor Agent → Contract Agent → Retrieval Agent → Verification Agent → Response Agent`
- **Output**: Details Frankfurt data sovereignty, 60-day subcontractor notice, and 99.95% uptime SLA under `CNT-VND-2024-001`.

### Demo 5: Permission & Access Control Security Gate
- **Query**: `"Show me the CEO compensation contract."`
- **When Role is Employee**: Access Denied; document content is blocked before LLM context construction.
- **When Role is Admin**: Access Granted; displays executive compensation and governance terms.

## Running the Application

### Requirements
- **Python 3.9 or newer** (tested on 3.12). No packages are required: the server, retrieval engine and database use only the Python standard library.
- Optional: `pip install pypdf` to upload PDF files (see `requirements.txt`).

### 1. Start the web server
```bash
cd enterprise-expert-knowledge-worker
python3 app.py            # Windows: python app.py
```
Open **http://127.0.0.1:8000/** in your browser. Use another port with `python3 app.py 8080`.

The first start creates any missing database tables and registers all policy files automatically. There is nothing to set up.

### 2. Try it
1. Click a demo chip, or ask *"Can I accept a gift from a supplier?"*, *"How long do I have to report a security incident?"* or *"What are the blackout periods for insider trading?"*.
2. Refresh the page: your conversation is restored from the database. Open older chats from **Chat History**.
3. Go to **Library → Upload Center**, drop in a document, then ask a question about it.
4. Switch persona (top right) to see role-based access: try *"What is the fraud investigation procedure?"* as Employee, then as Legal.

### 3. Run the automated tests
```bash
python3 -m unittest discover -s tests -p "test_*.py" -v
```
The new tests use a temporary database, so your data is left alone.

### Where things are stored
| What | Where |
| :--- | :--- |
| Chats, uploads catalogue, audit logs, approvals | `data/enterprise.db` (SQLite) |
| Uploaded files (normalised to markdown) | `data/uploads/<category>/` |
| Built-in policies, products, contracts | `data/policies`, `data/products`, `data/contracts` |
| FAQ, Updates and roadmap text | `data/site_content.json` |

To reset all chats, stop the server and delete the rows in `chat_sessions` / `chat_messages`, or delete `data/enterprise.db` (it is rebuilt with demo data on the next start).

### Security notes
- The role switcher is a **demo persona selector**, not real login. Anyone who can reach the server can choose any role. Add real authentication (e.g. SSO) before exposing it.
- The server listens on `127.0.0.1` only. To share it on your network use `HOST=0.0.0.0 python3 app.py`, and only on a trusted network.
